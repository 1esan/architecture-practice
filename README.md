# Architecture Practice

Локальный тренажёр системного анализа: **проектирование API, выбор интеграции и системный дизайн**. Интерфейс и задания на русском языке.

В банке 216 заданий: по 60 основных и 12 мини-кейсов на каждое из трёх направлений.

## Что можно делать

- Последовательно уточнять требования, фиксировать факты, источники и предположения.
- Проектировать одну API-операцию: поля, успешный ответ, статусы и основные ошибки.
- Выбирать и сочетать 22 способа интеграции с обоснованием, потоком и восстановлением.
- Решать задачи системного дизайна, рисовать схему, считать нагрузку и защищать решения.
- Сохранять попытки и черновики, смотреть прогресс, экспортировать/импортировать историю.
- Получать разбор от ИИ при подключённом совместимом локальном адаптере.

## Быстрый запуск

Нужен Python 3.10+; дополнительные Python-пакеты не требуются. Для разработки и тестирования также нужен Node.js 20+.

```sh
python3 -B server.py
```

Откройте **http://127.0.0.1:8784/**. Сервер слушает только loopback. Для остановки нажмите Ctrl+C. На macOS можно запустить `Запустить.command`: он запускает сервер в фоне и открывает браузер. Не запускайте одновременно копии проекта на одном порту.

Можно открыть `index.html` напрямую: подготовленные уточнения, редакторы, самостоятельная оценка и история работают без сервера. В этом режиме история хранится только в текущем браузере; ИИ недоступен.

## ИИ — необязательное подключение

Без адаптера приложение работает, кроме свободных ответов заказчика и ИИ-проверок. Адаптер не входит в этот репозиторий; это отдельная локальная служба, совместимая с контрактом ниже. Обычный OpenAI endpoint нельзя подставить вместо него без адаптации.

По умолчанию ожидается `http://127.0.0.1:8766`; адрес задаётся `TRAINER_ADAPTER_URL`, модель — `TRAINER_MODEL`. Ключ читается из локального файла `.state/adapter-key` или пути `TRAINER_ADAPTER_KEY_FILE`. Не добавляйте ключ в Git. Файл с ключом создайте через свой менеджер секретов и ограничьте доступ владельцем.

```sh
cp .env.example .env
# Отредактируйте .env без добавления в Git. Затем:
set -a; source .env; set +a
python3 -B server.py
```

Переменные из `.env` применяются оболочкой; автоматической загрузки dotenv нет. Приложение принимает адрес адаптера только на loopback и не отправляет ответы на внешний URL напрямую. Сам адаптер может передавать данные провайдеру ИИ — проверяйте его настройки.

Минимальный контракт адаптера: 

- `GET /api/status` с `Authorization: Bearer <local-key>` возвращает `models` (список slug или объектов со `slug`) и `sharing` со значением `verified` либо объектом `{"verified":true}`. Модель должна присутствовать в списке.
- `POST /api/chat` принимает `{"model":"...","stream":false,"messages":[...]}` и возвращает `{"done":true,"model":"...","message":{"content":"..."}}`. Содержимое ответа должно соответствовать запрошенной JSON-схеме.

Вызовы ИИ запускаются вручную; автоматического повторения платных запросов нет. Оценка модели — обратная связь, а не объективный экзамен.

## Хранение и безопасность

История SQLite и журнал сохраняются в `.state/` и исключены из Git. Браузер также держит локальную копию. Резервную копию можно скачать через интерфейс; файлы экспорта могут содержать ваши ответы и не должны попадать в репозиторий.

Скрытое досье заданий хранится на сервере в `data/` и не включается в клиентскую сборку. Это учебный механизм, а не защита содержимого от владельца исходников: в открытом репозитории досье доступно для чтения. Не размещайте сервер на публичном адресе — он рассчитан на одного пользователя локального компьютера.

## Разработка

После изменения JavaScript, CSS или банка пересоберите HTML:

```sh
python3 -B build.py
```

Запуск всех проверок без настоящего адаптера и ключей:

```sh
python3 -B -m unittest discover -p 'test_*.py'
node scripts/test-js.cjs
python3 scripts/check-release.py
```

CI выполняет тесты, проверяет пересборку HTML и запрет публикации локальных данных.

Основные файлы: `server.py` — HTTP/SQLite/адаптер, `scenarios.py` — досье и публичная часть, `data/` — банк, `app.js` — приложение, `focused-practice.js` — предметные редакторы, `workbench.js` — схема и этапы решения, `requirements.js` — интервью и записи, `core.js` — состояние и валидация.
